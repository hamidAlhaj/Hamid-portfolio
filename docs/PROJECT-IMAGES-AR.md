# تحديث بطاقات المشاريع وإدارة صور التفاصيل

## تطبيق التحديث

انسخ ملفات هذا التحديث إلى مشروع Hamid-portfolio بنفس المسارات، ووافق على استبدال الملفات الموجودة. التحديث لا يتضمن ملفات .env ولا يعدّل بيانات قاعدة البيانات، ولا يحتاج migration أو seed جديدًا.

أوقف تيرمنال admin بـ Ctrl+C، ثم نفّذ:

```powershell
cd C:\Users\Dragon\Desktop\Hamid-portfolio\admin
npm install
npm run build
npm start
```

اترك الباك إند داخل server شغّالًا. إذا واجهة الموقع تعمل عبر npm run dev، حدّث الصفحة بعد نسخ ملفات client.

## إصلاح More projects

أصبحت مساحة أغلفة البطاقات بنسبة ثابتة 16:10، مع محاذاة بداية النصوص وأزرار البطاقات. الصور تظهر كاملة داخل المساحة المخصصة. يوجد اختصار للوصف الطويل داخل البطاقة؛ الشرح الكامل يبقى في صفحة المشروع.

بطاقات GitHub البيضاء أو لوغو المكتبة هي الصور المخزنة حاليًا في بيانات المشاريع. لا يمكن تحويلها تلقائيًا إلى screenshots حقيقية؛ استبدلها بلقطات فعلية من تطبيقك عبر حقل Cover image.

## إضافة صور إلى تفاصيل المشروع

1. افتح http://127.0.0.1:4310 مباشرةً من المتصفح.
2. افتح Projects، ثم Edit بجانب المشروع.
3. انزل إلى **Project screenshots**.
4. من **Upload project screenshots** اختر صورة أو عدة صور من جهازك.
5. انتظر ظهور المعاينات وانتهاء الرفع.
6. استخدم ↑ و↓ لترتيب الصور، أو Remove لإزالة صورة من المشروع.
7. اضغط **Save changes**.
8. حدّث الموقع وافتح Explore project. الصور تظهر في قسم Project screenshots بصفحة التفاصيل، ويمكن الضغط عليها لفتحها بالحجم الكامل بتبويب جديد.

**Cover image** هو غلاف البطاقة. **Project screenshots** هو ألبوم الصور داخل صفحة التفاصيل. تعديل أحدهما لا يغير الآخر.

يمكن أيضًا إضافة رابط صورة يدويًا باستخدام + Add image URL. لا تترك صفًا فارغًا إذا لا تحتاجه؛ يمكنك إزالته عبر Remove.

## الرفع المحلي بدون S3

عندما يكون PORTFOLIO_API_URL في admin/.env موجّهًا إلى باك إند محلي مثل:

```env
PORTFOLIO_API_URL=http://127.0.0.1:3000/api
```

يحفظ الداشبورد الصور داخل:

```text
client/public/images/uploads/
```

تُولّد أسماء آمنة للصور وتُحوّل إلى WebP. المسارات الناتجة تحفظ في سجل المشروع بقاعدة البيانات بعد الضغط على Save changes. المجلد يبقى على جهازك بعد إغلاق البرنامج.

تعمل هذه الطريقة أيضًا لصور الغلاف والصورة الشخصية وأغلفة المقالات والأيقونات المخصصة. ملفات PDF تستمر باستخدام إعداد التخزين السابق، أو ضع CV يدويًا داخل client/public/cv.pdf واستخدم /cv.pdf في حقل CV PDF.

إذا أصبح الباك إند مستضافًا، يتحول الرفع إلى التخزين الدائم المهيأ على الباك إند؛ الرفع المحلي لا يعمل مع الباك إند البعيد، لأن مسار ملف على جهازك لن يجعله متاحًا تلقائيًا على موقع مستضاف.

عند نشر صور محلية مستقبلًا، يجب تضمين مجلد الصور في بناء الواجهة ونشره. تغيير الصور محليًا وحده لا يحدّث ملفات الاستضافة تلقائيًا.

## حدود الصور والحفظ

- حتى 12 صورة في ألبوم المشروع.
- حتى 8 MB للصورة الواحدة.
- الصيغ: JPEG، PNG، WebP.
- يتم فحص محتوى الصورة الفعلي وتحويلها، وليس الاعتماد على الامتداد فقط.
- SVG المرفوع مرفوض.
- إزالة الصورة من الألبوم لا تمسح الملف من القرص تلقائيًا، حتى لا ينكسر استخدامه في مكان آخر.
- صورة رُفعت ولم يُحفظ المشروع بعدها قد تبقى على القرص بدون ارتباط بسجل المشروع.
- احتفظ بنسخة من مجلد uploads ومن قاعدة البيانات؛ نسخ أحدهما وحده لا يكفي لاستعادة الصور مع ترتيبها وروابطها.

## إذا لم تظهر الصور

- تأكد أن الرفع انتهى وأنك ضغطت Save changes.
- حدّث صفحة المشروع العام.
- جرّب فتح رابط الصورة مباشرةً في الموقع.
- إذا ظهر Cannot save the image، تحقق من صلاحية الكتابة داخل client/public/images/uploads.
- إذا ظهر Unauthorized، راجع تطابق ADMIN_API_KEY بين server/.env وadmin/.env، ثم أعد تشغيل العمليتين.
- هذه الإضافة لا تنشر الموقع خارجيًا ولا ترسل صورك لأي خدمة عندما يكون الرفع في الوضع المحلي.
